1. REGRA PRINCIPAL: O CONTEÚDO AGORA MORA NO HTML
====================================================================

Há uma página estática por idioma, todas na mesma ordem de leitura:
  inicio -> trabalho -> pesquisa -> sobre -> contato
  PT-BR: Portfolio/wwwroot/index.html
  ES:    Portfolio/wwwroot/es/index.html
  EN:    Portfolio/wwwroot/en/index.html
  FR:    Portfolio/wwwroot/fr/index.html

Textos, datas, fichas, contatos, apoio, serviços publicados, links e galerias
são escritos diretamente nesses HTMLs. Não copie esses textos para JavaScript.
Ao corrigir um fato, atualize as quatro versões sem alterar IDs ou URLs.
O mesmo conteúdo publicado fica disponível com JavaScript desativado.
Os registros usam details/summary nativos e as fichas usam dl/dt/dd.

Para editar conteúdo: index.html.
Para reconhecer aparência: css/style.css.
Para reconhecer interação: js/app.js, js/shader.js e js/audio.js.
Não é necessário alterar esses códigos para corrigir uma frase ou legenda.

projects.js contém somente window.SERVICES: sete objetos com id, label, line
e status, usados como referência de serviços, não como cópia do portfólio.
Os cinco OK são publicados manualmente no HTML; os dois CONFIRMAR ficam fora.
app.js não usa essa lista para montar o conteúdo. Não escreva descrições de
trabalhos, biografia ou legendas nesse script; essas correções vão no HTML.

Consulte o README para o comportamento atual e os resultados de validação.
Nenhuma etapa de manutenção publica o site automaticamente.

2. ABRIR E ENCONTRAR O TEXTO CERTO
====================================================================

1) Abra Portfolio/wwwroot/index.html no editor e também no navegador.
2) Use Ctrl+F no editor para procurar uma frase EXATA que aparece na página.
3) Faça uma alteração pequena, salve em UTF-8 e recarregue o navegador.
4) Confira a seção, o registro e os links afetados. Não altere arquivos

participa do deploy estático. Não instale dependências para editar textos.

3. CORRIGIR UMA FRASE OU CRIAR UM PARÁGRAFO
====================================================================

Exemplo: procure id="bio" e altere apenas o texto entre <p> e </p> dentro
desse elemento. Preserve id="bio" e as tags que delimitam o trecho.
Não há outro resumo sem JavaScript para atualizar: é o MESMO parágrafo.

Para a chamada principal, procure class="hero-line" em #inicio:
  <p class="hero-line">Imagem, som e luz para ativar espaços, memórias e formas de criação coletiva.</p>
As alternativas no comentário seguinte não são texto publicado (D1).

Para separar parágrafos, use dois elementos <p>, não um campo de JavaScript:
  <p>Primeiro parágrafo aprovado pelo artista.</p>
  <p>Segundo parágrafo aprovado pelo artista.</p>
Esse exemplo é apenas um modelo; não o publique como redação definitiva.

Cuidados de HTML:
  - Não apague </p>, </div>, </details> ou aspas de atributos ao editar texto.
  - Use &amp; para um & em texto ou URL, &lt; para < literal e &gt; para >.
  - Dentro de atributo entre aspas duplas, use &quot; para uma aspa literal.
  - Caminhos usam /, nunca barra invertida.
  - Salve em UTF-8 para manter acentos e o nome Calderón Vargas.
  - Comentários <!-- ... --> são rascunhos ocultos. Não use -- dentro deles
    e não crie comentários aninhados.

Escreva na voz do artista. Data, autoria, função, instituição, equipe, local,
resultado, estado operacional e permissão são fatos: publique só o confirmado.
Se falta informação, omita o dado ou mantenha um comentário de pendência.
Não transforme nome de arquivo, aparência de imagem ou texto antigo em prova.

4. ACRESCENTAR UM TRABALHO COM DETAILS E FICHA DL
====================================================================

Escolha Trabalho ou Pesquisa e insira o registro dentro da seção correta,
antes do parágrafo final class="continuity". Não crie outra seção principal
só para um registro e não escreva uma cópia em projects.js.

Modelo estrutural (os textos e o ID abaixo são marcadores a substituir):

  <details id="novo-trabalho" class="record">
    <summary>
      <h3>Título aprovado</h3>
      <span class="summary-line">Resumo aprovado.</span>
    </summary>
    <div class="record-body">
      <p>Descrição aprovada em primeira pessoa.</p>
      <dl>
        <dt>Atuação</dt>
        <dd>Função confirmada pelo artista</dd>
      </dl>
    </div>
  </details>

Inclua período apenas se confirmado, por exemplo em span class="period".
Cada dt (nome do dado) deve ter seu dd (valor). Não preencha linhas vazias
com suposições. Um estado "Em desenvolvimento" não é uma data.
Não coloque links ou botões dentro do summary; deixe-os no record-body.
Para um subregistro, use details class="record nested" dentro do record-body
correspondente, como ocorre em Sucata Quântica e Eletrônica embarcada.

Um link interno, já existente e válido, pode ser escrito assim:
  <a href="#mestrado">Pesquisa de mestrado</a>
Com JavaScript, a navegação abre o destino e seus details ancestrais. Sem
JavaScript, os registros continuam abrindo pelo summary; confira o link no
navegador escolhido. O código não gera o novo registro automaticamente.

9. IMAGENS RESPONSIVAS: SRCSET EXPLÍCITO
====================================================================

Variantes não são descobertas automaticamente pelo nome. Declare apenas
arquivos que EXISTEM em img/responsive/. Cada descritor 480w, 720w ou 960w
deve corresponder à largura real daquela variante.

Exemplo real de source da primeira imagem VIVITAR, antes do img:
  <source type="image/webp"
    srcset="img/responsive/vivitar-analogica-01-480.webp 480w, img/responsive/vivitar-analogica-01-720.webp 720w"
    sizes="(max-width: 600px) 80vw, 420px">

Mantenha img src="img/vivitar-analogica-01.jpg" como alternativa e href do
link apontando ao original. Outras fotos VIVITAR têm variantes 480/960;
não copie 960 para a primeira foto, cuja variante maior é 720.
Se não há variantes, use só picture/img: não declare arquivos fictícios.
Ao alterar um arquivo, confira original, srcset, dimensões, alt e legenda.
Verifique no painel Rede do navegador qual resolução foi realmente usada.
Imagens ausentes não têm garantia de ocultação automática no app atual;
confira a visualização e os erros de carregamento, não só o console.

A área #demo-stage permite experimentar os cinco efeitos. #demo-mode troca

limpa a prévia e desliga sensores. A galeria mantém a rolagem horizontal.
A prévia usa o mesmo createShader, qualidade 0/DPR máximo 1, e pausa fora
da tela, com página oculta ou em Ambiente. Não crie instâncias duplicadas.

A demonstração em #demonstracao pede microfone e orientação só ao clicar
nos botões respectivos. Outro clique ou Esc desliga; clique durante a espera
cancela. Áudio é analisado localmente: não grava, envia nem reproduz a voz.
RMS, graves 60–400 Hz, agudos 1.800–6.500 Hz e ataques alimentam os cinco
shaders com suavização; FFT 2048, atualização 32 ms (400 ms em movimento
reduzido). Privacidade fica em details.demo-permissions; os estados e erros
permanecem visíveis fora dele.
Sair de Início, abrir uma foto, entrar em Ambiente, ocultar ou abandonar a
página desliga as entradas; voltar não as religa. Orientação calibra na
primeira amostra e informa quando o aparelho não fornece dados por 6 s.
HTTPS/localhost e permissões do navegador são necessários; arquivo local
pode ter restrições. Fotos nunca são deformadas. Movimento reduzido mantém
só intensidade discreta, sem parallax. Sem JS, fotos/textos permanecem.
Mensagens ficam nos data-* de #mic-status/#motion-status e data-off/data-on
dos botões, traduzidas nos quatro HTMLs. Preserve esses atributos ao editar.
Microfone real em celular e sensores físicos ainda precisam ser conferidos.

API preservada de createShader(canvas): setTarget, addStain, releasePointer,
clearStains, pulse e params (speed, warp, pigment), mais invalidate e stats.
setInput(level,x,y,bass,treble,attack): intensidade e bandas 0–1; orientação
−1 a 1. Os três últimos argumentos são opcionais. Movimento reduzido mantém
apenas intensidade luminosa, sem deformação, deslocamento ou ataques.
setPointer(x,y,vx,vy) influencia o campo sem tinta; setActive(false/true)
suspende/retoma o agendamento da instância.
stats() informa quality, dpr, frameDelay, backend, frames, stains, stainCoords,
target, mode, previousMode, mix, active e input (level,x,y,bass,treble,attack).
Coordenadas: 0–1, origem superior esquerda.
A instância shader é local em app.js: use o depurador nesse escopo, não
window.shader e não crie outra instância no mesmo canvas para conferir.
frames é acumulado; em movimento reduzido, confira que não avança
continuamente em repouso. Diagnóstico não comprova contraste ou aparência.
